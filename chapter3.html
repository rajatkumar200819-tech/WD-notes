Chapter 3: XML (Extensible Markup Language)

Detailed notes based on Punjabi University Web Development syllabus.

1. Introduction to XML

1.1 What is XML?

XML stands for Extensible Markup Language. It is a markup language used to store, organize and transport data in a structured format.

XML allows users to create their own tags to describe the information stored in a document.

1.2 Features of XML

  • XML is extensible because users can create custom tags.
  • It is platform independent.
  • It stores data in a structured format.
  • It is both human-readable and machine-readable.
  • It is case-sensitive.
  • It separates data from presentation.

1.3 Uses of XML

  • Data storage and transportation.
  • Sharing information between different applications.
  • Configuration files.
  • Web services and data exchange.
  • Storing structured information.

1.4 XML Example

<student>
    <name>Rahul</name>
    <rollno>101</rollno>
    <course>B.Tech CSE</course>
</student>

This example stores student information using meaningful custom tags.

2. XML Syntax and Structure

2.1 Basic XML Structure

An XML document contains elements arranged in a hierarchical structure. It generally has one root element containing all other elements.

<?xml version="1.0" encoding="UTF-8"?>

<college>
    <student>
        <name>Aman</name>
        <department>Computer Science</department>
    </student>
</college>

2.2 XML Elements

Elements are the basic building blocks of an XML document. An element generally consists of an opening tag, content and a closing tag.

<name>Aman</name>

2.3 XML Attributes

Attributes provide additional information about an element. They are written inside the opening tag.

<student id="101">
    <name>Aman</name>
</student>

2.4 Difference Between Elements and Attributes

  • Elements contain data or other elements.
  • Attributes provide additional information about an element.
  • Elements use opening and closing tags, while attributes are written inside a tag.

2.5 XML Comments

Comments are used to explain XML code and are ignored by the XML parser.

<!-- This is an XML comment -->

3. Well-Formed XML Documents

A well-formed XML document follows all the basic syntax rules of XML.

3.1 Rules of Well-Formed XML

  1. An XML document must contain exactly one root element.
  2. Every opening tag must have a matching closing tag, except empty elements.
  3. Elements must be properly nested.
  4. XML tags are case-sensitive.
  5. Attribute values must be enclosed in quotation marks.
  6. Special characters must be written using valid XML entities when required.

3.2 Correct XML Example

<book>
    <title>Web Development</title>
    <author>Aman</author>
</book>

3.3 Incorrect XML Example

<book>
    <title>Web Development</author>
</book>

The incorrect example has mismatched tags and is not well-formed.

4. XML Declaration and Namespaces

4.1 XML Declaration

The XML declaration specifies information about the XML document, such as its version and character encoding. It is generally written at the beginning of the document.

<?xml version="1.0" encoding="UTF-8"?>

4.2 Important Parts

  • version: Specifies the XML version.
  • encoding: Specifies the character encoding used by the document.

4.3 XML Namespaces

XML namespaces are used to avoid naming conflicts between elements that have the same name but different meanings.

A namespace is commonly declared using the xmlns attribute.

<root xmlns:info="https://example.com/info">
    <info:name>Aman</info:name>
</root>

4.4 Advantages of Namespaces

  • Prevent naming conflicts.
  • Identify the vocabulary to which an element belongs.
  • Allow different XML vocabularies to be combined.

5. Document Type Definition (DTD)

5.1 What is DTD?

DTD stands for Document Type Definition. It defines the legal structure and elements of an XML document. It specifies which elements and attributes are allowed and how they are arranged.

5.2 Types of DTD

  • Internal DTD: Defined inside the XML document.
  • External DTD: Defined in a separate file and linked to the XML document.

5.3 Internal DTD Example

<?xml version="1.0"?>
<!DOCTYPE student [
    <!ELEMENT student (name, rollno)>
    <!ELEMENT name (#PCDATA)>
    <!ELEMENT rollno (#PCDATA)>
]>

<student>
    <name>Aman</name>
    <rollno>101</rollno>
</student>

5.4 External DTD Example

XML document:

<?xml version="1.0"?>
<!DOCTYPE student SYSTEM "student.dtd">

<student>
    <name>Aman</name>
    <rollno>101</rollno>
</student>

External file named student.dtd:

<!ELEMENT student (name, rollno)>
<!ELEMENT name (#PCDATA)>
<!ELEMENT rollno (#PCDATA)>

5.5 Important DTD Declarations

  • ELEMENT: Defines an XML element.
  • ATTLIST: Defines attributes for an element.
  • PCDATA: Represents parsed character data.
  • DOCTYPE: Declares the document type and its DTD.

5.6 Advantages of DTD

  • Defines the structure of XML documents.
  • Helps maintain consistency.
  • Allows validation against declared rules.
  • Supports data exchange between applications.
